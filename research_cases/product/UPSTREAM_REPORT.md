# 上游候选与局部判断：真实使用记录

本阶段按用户纠偏改变信息流：程序准备材料 → dsh v4.1flash 提议原件绑定关系 → Jev 批量局部判断 → 全新强 Agent 选择调查、复算和重构表示 → 新局部问题回流。此前宿主主导的三臂结果保留在 [PHASE1_REPORT.md](PHASE1_REPORT.md)，不拿它证明本链收益。

## 实际运行

独立准备者从此前冻结的完整 A 材料中，按固定哈希与目录/格式轮转选择 96 文件、36 个目录家族，未用科学答案或已知关键文件选择。32 份代码、32 份结构化文本、32 份历史文本共 982,540 bytes；每份最多捕获 7,000 bytes，46 份为片段。选材规则与哈希保留；这不是全项目科学覆盖，原始长日志、轨迹和遗漏关系可在后续调查中补读。案例选材代码不进入 core。

实际 dsh 配置为 `deepseek-official / deepseek-flash / high`，安装 provider 将该模型标为 **DeepSeek-V41-Flash**；未修改默认设置。三个成功 worker 分别给出 30/20/40 个候选，共 90 个，全部精确引文检查通过。一次并发启动报配置格式错误，保留 stderr，待其余任务结束后单独重试成功。此前 Luna 试跑单列，不计入正式结果。

Jev 在科学节点仍为 **0** 时完成 90 个真实请求，159,051 输入 / 4,419 输出 token。原始请求、模型、分布和错误保存在 workspace 与导出 store；它们不是科学事实或支持票数。程序只保证引文、版本和来源绑定，未增加科学节点类型或概率门槛。

## 队列怎样影响了真正的调查

全新强 Agent 只先看队列前 15 项，自行选取三个承重问题。它读取 17 份原件，完成独立周期图绕行计算、预测表计数和三条时间序列表复算，保存 11 个科学节点及 7 节点 Spine，并绑定三个候选收据。

- HKUST 全窗最小值 0.0333747 Å 与实际周期贯通瓶颈 3.9208 Å 不等价；首次评分输入错误由计算见证确认。
- run2 整体误报分母为 13，摘要的 2/10 是一折指标；更正不改变已触发的路线止损。
- 已存代理无阈值跨越是窄条件负结果，不能宣布所有客体开门机制被排除；宿主没有照抄 Jev 的局部标签。
- 宿主补出 R3 动态 q95 被 R4 CALF 直接复用的来源链，不能当两轮独立机制证据。这个关联未在其已看前 15 项中表达，不声称全部 90 项均无此关系。

模型可见原件文字约 79,450 bytes；程序读取 810,572 bytes，均含重读，不是总 token 或总成本。独立评价者核对 136 文件导出哈希、阅读来源，并在独立 scratch 重放核查，输出完全一致。Agent 隔离依靠任务指令，阅读日志没有强制完整审计。

## 冷接手与回流

另一个新 Agent 只用冻结包独立完成时间稳健性检查：Kr 的相对变窄在五个时间块中稳定，Xe 早期与后期不同，全程中位数掩盖时间异质性。因此后续选帧应覆盖早晚阶段，不能据此推断客体因果效应、平衡或真实开窗。六个输入哈希和核查结果已独立重放。

原交接首选的几何任务缺坐标及 CALF 几何输入，这是真实缺口；替代核查成功没有消除它。随包方法已要求在下一步建议中注明必需输入及是否已捕获，未增加发布门禁。

强 Agent 形成的两个新局部问题又实际提交给 Jev：计算复用判为 derived，宽域排除的范围关系不足以确立。随后新 B 材料先与当前理解生成 7 项影响候选，再由宿主阅读原件决定修订；具体变更与独立复核保存在本目录 `upstream/`，不让 affected 自动改写科学状态。

B 冻结包为 r275、16 节点：原 11 节点中 8 个数据和版本完全保留，3 个修订、5 个新增，没有删除历史。独立复核重放通过。初次 B 发布仍把已完成的谱系判断列作 next；宿主读回 Spine 后修正了这一行动，第一次发布和修复分别保留。

又一个未见过纠偏过程的新 Agent 从 B 包接手，按当前 Spine 完成 Stage1 准备度盘点，恢复已有 20-run 验证、8 条邻窗 overlap 通过但 ESS/块稳态失败，以及具名 long 修复计划。它没有重复初级 pilot，也没有把未捕获的 long 结果说成已执行或未执行。这是完成 B 指定后续任务后得到的新成果，随后用已有记录机制回写；不是用参考答案重测原 B。六份来源和摘要算术通过独立核查，ESS 未从原始时序重新计算。

## 明确保留的失败与成本

独立按固定规则抽查 12 项发现：复述被误当直接支持、同输入重跑被误当独立证据、历史陈述被拿来判断行动是否过时、计划被误当已取得的观测。若干 scope 判断只是同一来源自比较。没有把这个目的性样本算成总体准确率。

针对已暴露问题，仅澄清通用局部问题和 worker 指令、标明局部上下文截断，并修复 node action 目标被 statement 覆盖的问题。三项原候选真实重问后，两项改为 compatible/derived；错误 action 目标仍被判 stale。原始 90 项成绩保持不变，失败继续保存；没有继续堆 gate 或为单例调阈值。

dsh 三个成功会话共 77 个生成步骤：原 adapter 累计输入 308,985、缓存读取 6,412,288、输出 131,601 token，其中报告 reasoning 68,677；各字段独立保留，reasoning 不再加到总数。头部会话命名请求未计入。这个 headless 调用方式有明显多轮工具读取开销，**尚未证明总成本低于强模型直接调查**。

正式上游及回流/修订共 99 次真实 Jev-1.13.0 请求，222,230 输入 / 4,825 输出 token；3 次已揭示重问另计。安装产物迭代见 `upstream/build-history.json`。A 冷读启动附近共享安装环境从 candidate-4 更新到 5，未记录逐调用 wheel hash，不能强称该次只用单一冻结构建；最终 B 冷读使用独立安装的 candidate-6。

软件有 142 项回归；最终 wheel 通过旧版 4+37、2.0 48、当前产品 4+30 项隔离安装/生命周期检查。新验收一度把预期拒绝误设为退出码 0；另一次开发输出目录重名导致回执收集失败。原失败保留，历史回执从原 sandbox 恢复，最终独立目录重跑通过。

目前证据证明上游信息流已实际进入科学结构形成，并能接手和继续修订。没有证明 Jev 必要性、总体准确率优势、提速、全 43,596 文件完成、跨学科或其他强 Agent 宿主的成功率。本阶段到可交付产品闭环收口，不据仍可想到的风险继续扩充架构。
