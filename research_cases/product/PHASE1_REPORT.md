# Research Retro 产品闭环实测

本轮已把 3.5 的强制流程改为宿主主持的复盘产品，并完成真实材料重建、冷接手和较晚证据修订。核心职责仍是来源、版本、依赖与可携交接；科学理解由强宿主完成。最终独立评价及修订复核见本目录 `evaluation/`，软件交付见 [安装包目录](../../releases/standalone-3.6.0/INSTALL.md)。

## 产品实际变化

- `start PROJECT --workspace W` 提供独立入口和随包宿主方法。一次 `record` 保存已完成的调查，不要求普通工作先 seal/reveal；困难争议仍可选用历史隔离流程。
- discovery 独立浏览材料家族，把真实调查发现保存成已有问题/路线/缺口。聚焦上下文只含所选材料，不再强塞六个无关文件。文件家族只是导航，不自动推断科学路线。
- `SPINE.md` 是宿主选择的短阅读顺序，正文来自当前节点；`RESEARCH_MAP.md` 保存完整细节。修订更新当前认识与行动，历史保留，失效依赖的旧建议不会继续作为主线建议显示。
- `judge` 接受显式、局部的 typed questions。保留真实请求、回答、模型、成本及错误；没有隐式模型调用或 0.8 门槛。已有窄范围授权不会自动扩张。
- `add-source` 接入新只读材料；核查脚本和结果可随包捕获，并明确标记为宿主核查产物。原科研项目不迁移、不修改。

没有新增科学 ontology 或本地领域 parser。r655 的理由/行动问题保留为通用修订回归，历史 3.5 实案与失败不改写为当前默认行为。

## 材料与受测方式

独立准备者选择 cxekr/cxekr_loop 的完整指定文档阶段：A 含固定提交
`66c482d95321b6134081b6ce33b2fbd9297ae016` 的完整普通跟踪文件、loop 除 r5 外的材料和完整 gt-reforge，合计 43,596 文件、4,704,096,936 字节。38 个 Git 符号链接仅记录元数据，不向外追踪。B 是真实较晚 r5 说明，9,532 字节；它是作者的新解释，未附新实验或计算输出。

三个新对话只得到产品（对照臂除外）、A 和用户目标，分别使用普通 repo tools、Retro、Retro + Jev。相同继承模型与推理配置，无科学答案或文件提示。参考答案由独立评价者先保存；材料按文档阶段隔离，**不是时钟一致的历史快照**。隔离依靠任务指令，非 OS 读权限封锁。完整协议见 [protocol.json](protocol.json)、[选材说明](SELECTION.md) 和 [原始目标](TASK.md)。

三臂没有等 token/tool 上限，开始时间交错且并行运行；不能从时间推断加速。没有完整强模型 token 账单或完整逐条终端转录，因此不编造总成本和零中断声明。

## 实际结果

| 要求 | 观察到的结果 | 限定 |
|---|---|---|
| 理解 | 三臂均恢复主要问题、研究对象/条件、路线与当前边界 | 非全历史逐文件重建；初次 A 均遗漏 v33 特定拒绝和 v105 来源链，B 修订后补入 |
| Discovery | 恢复旧有限温度研究，发现当前几何汇总与周期路径不等价；纠正误报分母 | 科学发现来自宿主原件调查，不能归因于文件曝光或 Jev |
| Reasoning | 真正重算周期图、指标和反例；直接工具臂的轨迹/日志核查最深入 | 图结论不等于动态开窗、输运或物理机制证明 |
| Mainline | 两个 Retro 输出分别有 19/17 个科学节点，短 Spine 与详情分离 | 单例评价；没有人类阅读计时或跨研究者研究 |
| Handoff | 新 Agent 仅凭捕获包完成新的中心/原子排列敏感性核查，保存脚本、数值与状态 | 首次 A 表述过宽后定向修正；无 Jev 臂未捕获两条轨迹，也未进行同等动态任务的冷接手，不能比较其表现 |
| Revision | 后续作者材料经原件核查后进入相关理解与行动；保留 18 个独立旧节点，更新 1 个、增加 3 个 | A 已识别主要问题，B 主要是收窄和加入条件路线，非强制翻转既有正确结论 |

具体承重发现包括：R4 全体误报分母为 13，保存的“留一”分数实际计算保留集合；全窗最小半径 0.0125172 Å 与周期绕行瓶颈 0.94142 Å 不等价。宿主构造了死边/绕行反例并实际计算，没有仅复述方法名称。评价者自己的参考分母也曾错误，已依据原件修正，初版与勘误均保留。

第一次冷接手在 2 条轨迹各 5 帧上完成原子列表排列敏感性检查。第二次新 Agent 只读 B 修订交付，在两温各 4 帧上独立检查；同一原子集合逆序使静态窗口中心改变 3.6053 Å。它没有将算子身份未通过时的较大路径值当作 Xe 开窗，也没有继承“必须马上新增 MD/PMF”的行动。两次任务彼此未共享核查结果；都属于读过交付摘要后的接手，不能称未知材料盲测。

## 三臂与 Jev

[首次三臂比较](evaluation/THREE_ARM_FIRST_COMPARISON.md) 在冷接手和 B 评价前冻结。普通工具臂对原始轨迹、协方差日志及论文检查更深入；两个 Retro 臂更明确恢复已执行的 v13 有限温度工作。三臂都识别主要几何问题。差异来自各一次调查的覆盖选择，尚未证明产品总体更准确或更快。

Jev 有一次真实 `jev-1.13.0` 请求：601 输入 / 60 输出 token，1,272.513 ms。它对已提供的局部支持、留一有效性和后续行动给出合理建议；输入里已含关键发现。没有记录到它新增发现、阻止错误或节省时间的证据，因此保持可选，不把调用成功写成科学收益。修订和冷接手无需额外 Jev 调用。

## 使用失败与修复

首次冻结结果未覆盖；后续修复有独立回执。

- 初始离线环境误选 free-threaded CPython，依赖 wheel 不兼容；保留失败，明确普通 CPython 3.14 后安装成功。
- `inspect` 曾输出约 46 MB；修为紧凑 CLI 输出，同一包 523 字节。旧 JSON 客户端保留兼容默认，可显式 `full:false`。
- 同路径核查脚本多版本曾难以解析；SOURCE_INDEX 增加所用节点/修订与捕获时间，保留每版哈希。
- 科学核查中的半径断言、平衡段和总体/样本标准差差异，以及记录协议失误均留在最初回执。
- 冷接手 A 初版把“中心身份未验证”写得像“缺少中心资料”；原件已有 `center_frac`。揭示后的修正收窄文字和节点，原数值、CSV 与初版状态均保留，不冒称第二次盲测。

软件修复后的 A 重新导出逐项保留原 19 节点内容和 revision；科学修订另计。浏览器脚本只做语法检查，未进行实际浏览器视觉测试。当前研究状态仍为 draft；这保留范围与未知，不妨碍已验证的接手用途。

## 回放与证据入口

`source-manifests.tar.gz` 保存 A/B 全部来源哈希，原数据留在独立外部空间，不装进产品。`checks/` 保存实际宿主核查脚本原样副本，仍带当时路径/依赖；在同一冻结材料或按脚本输入重建的副本上运行。它们是案例脚本，不是核心 parser，也不是自动决定科学真值的验收器。

开发和评价回执在 `var/retro-product/`；本目录保存独立评价、来源清单和脚本，发布目录 `receipts.tar.gz` 保存可分发的软件验收与选定研究回执。实际外部工作区位于 `/home/sun07ao/retro-workspaces/retro-product-evaluation/`，入口和哈希在 `receipt-index.json`。

实测范围是一个完整选定研究阶段、当前 Codex 宿主和 Linux/CPython 3.14.4。其它学科、Agent 宿主、平台以及反复增量使用仍未实测。本轮到这个产品闭环收口，不据单例继续添加科学门禁。
