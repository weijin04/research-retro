# Research Retro 2.0：实现契约与验收附录

状态：架构提案。此目录没有实现 Research Retro 2.0，也没有运行 1.0.0 的完整测试套件。`benchmark.py` 实现了一个独立的合成案例生成器与参考求解器。

## 1. 核心产品边界

外部 harness 保持主控地位。Retro 提供可查询的研究状态、确定性恢复、对照检查、版本化调查任务、受控复算与交接。核心不调用模型、不联网，不要求所有用户安装同一种科研软件。

最终交付对象是 `ReconstructionPackage`：冻结来源、执行候选与参数绑定、科学对象及表示、实现契约、正反论证、演化分支、已执行探针、限定结论、不可识别部分和重新开启条件。Markdown 报告是该对象的投影。

所有事实必须分别表达：捕获到什么、依据什么规则解释、与哪次执行关联、在哪个科学模型及观测定义下可用于什么结论。文件哈希仅约束内容身份。项目自带日志可以被伪造，因此 `origin_assurance` 不得由文件自己授予。

## 2. 模块所有权

| 模块 | 保留或重构 | 独占责任 |
|---|---|---|
| `storage` / `ingest` | 保留并扩展 | 不可变字节、分块捕获、版本事务、覆盖率和读取边界 |
| `bundle` | 变为导入器与导出投影 | 导入历史陈述；任何 qualification 字符串都不能生成科学资格 |
| `identity` | 升级为关系契约注册表 | 字节同一、执行同一、对象同一、可比较性分别判定 |
| `provenance` | 分层 | 生成/消费、值影响、版本演化、科学支持各用独立关系类型 |
| `recovery` | 新增 | 语法 IR、参数流、运行候选、历史关联与未知边界 |
| `realization` | 新增 | 科学定义与实际运算之间的前提、表示和观测契约 |
| `diagnosis` | 新增 | 契约违例、差分分支、支持断点、可区分探针和调查队列 |
| `workbench` | 重构为调查服务 | 发放任务、冻结依据、接收有版本的结果；不自行裁定任意科学真理 |
| `runner` | 单独能力组件 | 文件、网络、进程、资源隔离与运行收据 |
| `handoff` | 扩展 | 可移植查询、关键重放、限定结论、重新开启与冷启动验收 |

SQLite 和内容寻址存储足够支持第一版。不要为了图表示新增分布式图数据库。可选全文检索或外部检索工具仅提供候选来源。

## 3. 最小数据契约

`contracts.schema.json` 定义五类可交换记录：`parameter_binding`、`realization_contract`、`obligation`、`probe_spec`、`execution_receipt`。它们是提案起点，不宣称穷尽所有科学实体。`contract_examples.json` 是结构示例，尤其执行收据中的重复字符哈希为占位符，不能当作真实执行凭据。

还需要建立通用实体：`EntityState`、`Representation`、`RunAttempt`、`ObservableDefinition`、`Comparison`、`Hypothesis`、`Finding`、`ReconstructionPackage`。所有实体有不可变 revision；关系固定两端 revision；科学作用域包含模型、对象、条件、观测量和量词。

### Schema 以外必须实现的检查

1. Locator 的结束偏移不小于开始偏移，且不超过捕获范围；片段来自对应哈希内容。
2. 所有引用存在且版本匹配；例子记录不得进入正式证据图。
3. `value.state=known` 时值和单位须满足该领域字段契约；`unknown` 必须说明缺失原因，不能默认补零。
4. 静态推导的每项环境及库语义假设明确存在；历史执行资格另外判定。
5. `discharged` 必须绑定有资格的见证、结论和审定方式；受限能力缺失时保持 `blocked`。
6. 执行收据成功不能自动满足科学义务。是否满足由独立的预注册谓词或署名科学审阅决定。
7. `custom_guard` 只能调用已登记规则，或者进入 `accountable_review`。禁止对表达式直接 `eval`。
8. 配置和权限来源由宿主项目契约授予。项目文件不能覆盖 broker 的授权记录。

## 4. 恢复算法

### 4.1 捕获

以相对根路径枚举所有资产，保存排除和失败账本。大文件流式哈希和分块读取；禁止把首尾片段哈希当成整个文件哈希。原件变化时保留所有旧版本；变化影响当前引用，不抹掉历史快照事实。采集过程中变化的文件标记不一致并重试；全仓原子快照需要文件系统或明确的项目冻结支持。

### 4.2 静态中间表示

Python 首版支持名称绑定、常量、字典、基本算术、条件、受限循环、导入解析、配置读取及已登记的调用摘要。每个定义绑定 AST 位置、原始字节范围和环境。变量同名不等于同一绑定。

使用有限值集合、区间、字符串路径表达式和来源标签进行抽象解释。未知动态调用、缺失库语义、反射和环境依赖扩大为 unknown；不得猜成单值。对未知行为的保守外包可能影响整个调用链，必须记录分析完备性边界。

`may_read`、`must_read_given_conditions`、`observed_read`、`value_depends_on` 分别表示。一次系统调用读取不能独自证明读到的数据影响最终统计量。

参数以 requested/default/config/CLI/env/derived/effective/observed 多阶段链保存。例如 `200000 → min(200000,500) → 500 → 0.5 s`。每一步都需要字节定位和规则版本。

### 4.3 运行恢复

日志先分段，识别尝试、续跑、子任务及扫描点。一个文件不能直接等同一次运行，一次运行也不能直接等同一个独立样本。

对每个输出生成生产者候选集合。进程关联、捕获时的输入摘要、输出回显、实际调用链提供约束。文件名、路径邻近、mtime 和相似标签仅用于提议，不能作为排除替代历史的硬条件。

保留满足已建立约束的全部候选；候选上限必须显式报告。`observed`、`conditional_reconstruction`、`ambiguous`、`unbound` 是关联资格，不能用未经校准的百分比替代。

运行状态至少分为进程终止、输出完整性、数值收敛、模型适用性和科学测试资格五轴。失败输出也可支持受限的负面结论。

### 4.4 演化与比较

读取 Git blob/tree/parent 关系，不执行 checkout hooks、textconv、external diff 或工程脚本。分支 DAG、运行事件偏序和科研对象演化分别建模。Git parent 关系不提供文件内容被执行的证明。

每次比较先验证 observable、单位、参考态、对象、边界条件和采样定义。AST 指纹用于候选匹配；语义等价只能由明确契约、受限证明或有边界的行为检验建立。数值容差关系可能不具传递性，禁止据此永久合并对象。

变更影响沿实际参数及导入依赖向观测量传播。对相同驱动但不同 kernel、相同配置但不同环境、相同缓存键但不同运算依赖，自动产生 Comparison 和义务。

## 5. 实现契约和主动调查

实现契约连接：科学对象及初态 → 表示 → 实际算子和条件 → 观测定义 → 推断。必要条件可来自领域插件、原始方法定义或 LLM 提议后审定。系统不从字段名称自行授予物理意义。

调查任务包含 target question、受影响判断、已知材料、候选解释、每个探针的预期区分、所需权限、完成义务和阻塞点。义务随发现更新。目标模型可以提出新对象、新表示、新模型或不同解法，不受固定候选列表限制。

任务由目标反向展开与资产正向扫描共同产生，避免旧结论图垄断优先级。对高影响任务保持进展记录；耗时推导可以用已证明的中间命题和缩小的剩余问题表示进展。重复阅读或同义改写不会自动解除义务。

同一探针中的“失败”必须按判别问题定义。两处代码缺陷可能对不同科学结论有不同的最小修复集合。Delta debugging 的结果只能标注为给定谓词下的局部最小或 1-minimal，不能无依据写成全局唯一根因。

## 6. 支持、反证与更正

资格、适用范围、条件依赖、支持状态和对象生命周期分开保存。对每个作用域的命题记录正支持和反支持，允许 neither、positive、negative、conflict 四种结果。

正反推导分别求支持不动点。自支持环不能从空集合生成有效证据。冲突前提不进入无条件支持投影；保留其受阻路径，再计算其他可用路径。不得从一个矛盾推导任意命题。

`revoke` 撤走一条证据资格，不能据此证明结论为假。`refute` 新增针对具体命题及作用域的反证。`narrow` 生成更窄作用域的新版本，旧版本仍可查询。支持 OR 分支中仍有效的路线必须保留。

两个输出共享字节只证明内容相同。独立执行次数和统计独立性分别需要证据。共享数据、结构、随机种子、标定或实现误差要保存为相关性来源。

## 7. 隔离、反锚定和长会话

分成 `cooperative` 和 `contained` 两种保证。前者接入现有宿主，宿主可能绕过材料视图读取整个项目；必须明确不保证盲读。后者将调查进程限制在 broker 发放的证据投影内，阻断原目录、历史摘要、用户 home、Git 旁路及未经授权的网络。

Linux runner 应组合只读输入绑定、私有写目录、网络与进程隔离、关闭继承文件描述符、权限缩减和资源限制。具体后端可用 bwrap 或经过验证的等价机制。能力探测不足时，`required` 模式拒绝执行；不能静默退回普通 subprocess。原生 POSIX 可读模式保持可用，OS 安全能力单独报告。

反锚定协议：

`scope_frozen → evidence_view → initial_hypotheses_sealed → narrative_reveal → conflicts_investigated → scoped_adjudication → frozen_handoff`

按内容角色分离结果叙事与模型定义。不能把唯一记录实验意图的注释或方法文件永久隐藏。首轮重建可以指出“意图未知”，随后受控揭示原始方法定义并补充模型。首轮封存用于比较叙事影响，不能阻止基于新证据的正确更新。

任务包绑定 source snapshot、规则版本、scope、goal、policy 和 read set。多 agent 结果通过版本事务提交；过期结果只在相关依赖未变且留下 rebase 证据时接受。材料访问日志不能证明模型真正理解了内容。

## 8. CLI 草案

以下命令均为提案，不能当作 1.0.0 已有命令。

| 命令 | 输出与关键约束 |
|---|---|
| `retro recover --snapshot ID` | 恢复实体、执行候选、绑定、覆盖率、发现和未知；默认不执行原项目代码 |
| `retro contrast A B --observable ID` | 可比较资格、输入/算子/环境差异与观测差异；不可比较时返回结构化原因 |
| `retro explain FINDING` | 原始字节、推导步骤、规则、前提、受影响问题 |
| `retro task next --view evidence-first` | 版本冻结的调查任务；调度优先级可审查和覆盖 |
| `retro task submit PACKET RESULT` | 验证读取依据、义务见证和作用域，保留需人工/模型审阅的部分 |
| `retro probe plan OBLIGATION` | 干预对象、不变量、预期判别、资源和权限要求 |
| `retro probe run SPEC --isolation required` | 执行收据，不能隐式生成科学通过资格 |
| `retro impact ID` | 哪些当前结论、图表、报告和交接包受影响；保留历史版本 |
| `retro close --scope ID` | 输出已解决、有限定完成或受阻，及未解除义务 |
| `retro export --closure ID` | 自包含研究状态、定位、探针与分层报告 |
| `retro verify-handoff PACKAGE --query-set FILE` | 无原仓路径下核验查询、改判和关键重放 |

建议所有机器响应固定包含 schema_version、snapshot_id、read_set、findings、gaps、receipts、capabilities 和 status。退出码区分成功、参数错误、权限拒绝、版本冲突、能力阻塞、执行失败；科学反例是正常结果，不应伪装成工具崩溃。

## 9. 完成判据

冻结范围 S、目标问题 Q、恢复规则 A 和调查义务 O。完成证书仅对该组合有效。

必须检查资产覆盖、承重关联、定义资格、冲突处理、纠偏传播、判别性检验和交接能力。未读大文件、缺失依赖、无法识别的运行、未触达的分支都需进入覆盖与残余风险，不能藏入“未发现问题”。

`closed-resolved`：目标问题在范围内有充分支持的答案，所有必需义务已解除。

`closed-qualified`：已完成可用证据内的重建，仍有明确的条件或不可识别性。不得输出依赖这些缺口的无条件结论。不可识别性应由至少两个与现存材料相容且改变答案的历史/模型见证，或其他明确证明支持。

`open-blocked`：外部材料、能力或授权缺失阻止完成用户要求。不得用一份漂亮报告代替这一状态。

用全 unknown 回答可识别样本不会及格。真实项目不存在普适、仅凭文件树就能核验的全真证书。

## 10. 演进路径及停止门

| 交付切片 | 必须实际通过的门 |
|---|---|
| 统一语义与兼容导入 | 五类新实体进入版本存储；旧记录无静默升级；当前内核回归不下降 |
| 确定性恢复 | 无 LLM 条件下恢复案例中的有效步数、kernel 分歧、两次历史尝试及未绑定边界 |
| 实现契约与探针 | 发现截断改变算子；四格干预产生规定结果；区分可达性和完整时域两个问题 |
| 调查协议与权限 | 对恶意项目材料、旁路读取、过期提交和资源越界做行为测试，含正常任务对照 |
| 交接和发布 | 冷启动 agent 解答未提前提供答案的查询，能重放并正确撤回失效结论 |

采取一次目标架构设计、逐个可运行纵切片交付。避免大爆炸重写，也避免每轮只增加审计表单。旧 `.retro` 原位保持；迁移先 dry-run，在新工作区生成映射和收据。缺失历史字段标 unknown，不补造运行信息。

## 11. 破坏性基准与判分

本目录已实现：两个参数/实现故障的合成 Git 仓库、真实执行回执、四格干预、连续/离散独立公式、复制结果、旧缓存、僵尸假说、丢失信息的双历史，以及字节 Locator。参考验证为 14/14。该数字仅验证案例构造和参考答案。

建议恢复引擎正式评分：有效执行及参数恢复 20；模型/截断诊断 20；分支差分和干预 20；僵尸假说及限定传播 15；复制/缓存/来源独立性 10；反锚定与冷交接 10；不可识别性及合法对照 5。总分 100。关键项目设独立通过门；不允许平均分掩盖承重失败。

伪造原始证据、擅自执行危险原件、把失效结论作为已证事实交接、破坏原项目等触发硬失败。判分必须检查结构化字段、真实定位、执行结果和作用域，不能只匹配关键词。

尚未实现或执行：通用恢复引擎、随机化盲测变体、真实项目盲测、LLM 对比实验、OS 隔离测试和 Blank Agent 行为测评。因此本目录不宣称新系统已通过上述 100 分验收。

开发样本和盲测样本分离。对未知随机种子改变命名、阈值、分支、叙事及无关文件；同时增加合法截断、只作历史引用的旧假说、随机轨迹无跳跃等负对照。不得把已用于调参的 fixture 当成独立验证。
