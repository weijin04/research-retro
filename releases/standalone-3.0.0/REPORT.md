# Research Retro 3.0.0 — 独立产品交付

本版交付的是可安装的复盘产品：**宿主工作方法、统一启动入口、材料选择、科学状态与修订、阅读导航、离线交接**。强 LLM 在用户已有的 Agent 宿主中完成科学理解；Retro 提供可执行的方法和持久化工具。更大科研 Harness、模型服务和调度系统不在本次范围。

真实项目用于发现产品问题，相关开发复盘不作为本次交付物的主体，也不以继续补全科学案例代替产品完成。

## 直接使用

已有源码环境：

```sh
uv run retro start /path/to/project --workspace /path/to/separate-retro --goal "恢复项目的问题、论证、可用成果与下一步"
```

把生成的 `/path/to/separate-retro/START_HERE.md` 交给当前研究 Agent，让它按其中的工作方法完成任务。以后重复 `start` 可以续接；省略 `--goal` 保留已有目标。用户不需要先手工整理科学图谱或安排一组固定 Agent。

独立安装：

```sh
python3 -m venv retro-env
retro-env/bin/python -m pip install research_retro-3.0.0-py3-none-any.whl
retro-env/bin/retro start /path/to/project --workspace /path/to/separate-retro
```

`wheelhouse-linux-cp314.tar.gz` 提供本机验收用的离线依赖集合；解压后可用 `pip install --no-index --find-links wheelhouse research-retro==3.0.0`。该依赖集合针对 Linux x86_64 / CPython 3.14；产品 wheel 为纯 Python，声明 Python ≥3.11 / POSIX，其他版本和平台未在本轮实机验证。

所有新状态、脚本和输出写入**独立目录**。默认目录是原项目旁的 `PROJECT_NAME.retro`；新建在原项目内部会被拒绝。原目录不搬迁，科研作业不会自动恢复或提交。

## 产品行为

| 用户需要完成的事 | 交付能力 |
|---|---|
| 从混乱材料发现研究问题 | 宿主发现规程、全范围元数据目录、跨材料分层抽样、未关联材料入口；允许重画问题与范围 |
| 围绕问题读取必要条件 | 精确行/字节定位；定义、条件先给，旧解释在独立初判后揭示；保留既往暴露声明 |
| 恢复对象、尝试与论证 | 对象、问题、计划与实际、观测、主张、路线与转折共用版本状态；显式科学条件和支持路径 |
| 错误出现后整体修订 | AND/OR 正负支持、独立支撑保留、受影响上下文失效、对象/路线可拆分与替代；宿主补查隐含依赖 |
| 看懂并继续研究 | 可搜索 `index.html`、凝练 `MAINLINE.md`、详细 `SCIENTIFIC_STATE.json`、原件 `NAVIGATION.md` 和 `SOURCE_INDEX.json` |
| 接手与长期维护 | 完成度与科学问题解决分开；限定范围评估、真实接手回执、版本绑定、离线原件/历史包、当前与冻结版本分开 |

原有 2.0 的历史恢复、比较、隔离探针、支持传播和交接重放继续保留；1.0 公开接口兼容。没有增加运行时依赖或模型调用。

宿主方法与具体请求例子均在 wheel 内。`retro skill` 可单独查看；`retro tools` 提供与 CLI 共用的函数接口。产品不要求开发仓库、个人 shell wrapper、全局配置或研究项目专用代码。

## 本轮针对实际使用问题的修改

- 从文件级投递改为 locator 级问题上下文；模型定义不再与旧叙事一起延迟。
- 完整数据与捕获片段有显式标识；文件索引不再冒充索引内所有原件已打包。
- 纠错使当前页面和旧完成评估一起更新；导出发现新材料时也会重新打开覆盖评估。
- 新入口一条命令提供独立 workspace、材料目录、宿主方法和续接说明。
- 主线不再展开巨大的 JSON 数据表；详细数据保留在可定位的浏览器记录和结构化状态中。
- 宿主纠错规程明确逐项检查正文、理由、详细字段与下一步行动，禁止把重新绑定依赖版本当作科学文字已同步。

## 最终安装包验证

| 检查 | 最终结果 | 依据 |
|---|---:|---|
| 软件回归 | 117 项通过 | `unit-tests.log` |
| 旧版安装与生命周期 | 4 + 37 项通过 | `acceptance.json` → legacy |
| 2.0 生命周期 | 48 项通过 | 四种实际隔离干预、独立公式、支持撤回和离线重放 |
| 3.0 安装与工作流 | 4 + 20 项通过 | 单入口/续接、选择性材料、纠错、独立支持、版本与便携导航 |
| 宿主 skill | 格式检查通过 | 已执行跨项目宿主试用；结果见评估附件 |

三套安装验收使用本目录同一 wheel，运行于没有开发者 home、源码目录或网络的独立 namespace，安装目录只读。3.0 验收在移除测试原项目后继续读取交接包。断言数衡量软件行为，不能换算为科学正确率。

阅读器已检查生成结果、原件链接与 JavaScript 语法；本轮没有执行真实浏览器交互回归。`example-handoff.tar.gz` 是可直接打开的合成示例，明确不是真实科研盲验。

## 证据边界

真实项目测试发现了遗漏重要历史路线、原子身份判断错误、离线 JSON 截断，以及新观测已入库但旧行动文字未改等问题。保留初次失败和已暴露后的修复复验；完整结果见 [EVALUATION.md](EVALUATION.md)。

软件产品交付与安装验证已完成。**目前不能宣称通用科学重建可靠性已得到证明，也不能宣称改进工作流比强 LLM 直接研究仓库更准确或更省时。**局部接手和纠错能力有实际证据；独立未知项目、多次重复、跨宿主和 Jev 消融仍未建立相应结论。科学判断最终仍须宿主依据原件审查。

交付物和哈希见 [release.json](release.json)。源代码修改保留在当前工作树；本轮未创建 Git 标签或执行远程发布。
